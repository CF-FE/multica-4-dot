# 分阶段验证方案 · v0.1

这是 v0.1 的历史验证方案。后续实施结果见[跨端汇报记录](workflow-reporting.md)，当前直连 MCP 的验收及回退见[工程任务](multica-backend-tasks.md)。

| 阶段 | 内容 | 放行门槛 |
|---|---|---|
| S0 基线 | 锁定 Multica 版本/镜像和 CLI；验证镜像可取；隔离目录、独立 PG17、试点账户；测试私网链路与非授权路径，评估 VPS 资源 | 本机 /readyz 成功且迁移可核；实际调用端能访问；非授权节点和公网无法访问；无 OOM/重启循环；有恢复证据 |
| S1 只读 | 优先用已授权工作机 CLI 读工作区 → 样本 Issue → 关联 Run；离线 fixture 验证工具，明确需要无人值守才推进 Vultr MCP | 样本具体引用可读，越权/跨工作区请求拒绝，凭据不进日志，错误和分页有界；Web、Daemon、CLI 分别验证 |
| S2 单任务闭环 | 预建样本 Issue，获一次明确派发许可；仅一机一 Agent；原 task 信箱回传、G8 在既有运行中核对 | 恰一条授权派发，映射吻合；可复核的持久化回执；来源与版本可证；重复及响应丢失时无额外 Run；未把完成报告当验收 |
| S3 可选增强 | 自动化事件、失败补偿、写权限、规模优化均分开处理；无即时 SLA 则保持轮询 | 认证与防重可靠，漏报能对账，来源失配可观察；事件失效能退回既有巡检；无需修改历史 |

## 验证清单

- **网络**：记录发起点、虚拟路径和观察时间；从实际 API 调用进程检验 `/health`，从服务自身检验 `/readyz`；另证 Web 登录后会话、反代 WS、Daemon 在线/认领观察。验证加密、受信中继、端口限制；公网与名单外的负例应失败。
- **容量**：采样冷启动、空载与单 Run 的 CPU、内存峰值、交换、磁盘、请求延迟与重启。先建立基线与试点上限，不拿 ICMP 或纸面规格作承诺。备份 DB 和上传卷，恢复到隔离实例，对照对象和上传样本再认定可恢复。
- **故障注入（只在隔离环境）**：断开虚拟链路、运行时离线、MCP 读取失败、结果写回超时、重复事件、原事件已读、看板内容中含操作指令、Run 终止无回执。未知状态不重派、不假报成功；对账冲突转人工。
- **观测**：记录连接/鉴权/去重拒绝、待确认映射、终止无回执、信箱消费延迟等；日志只留受控标识、观测时间、组件和错误码。Run 来源与信箱来源分别记账。
- **回滚**：禁用试点 MCP / 回调和独立凭据，停止新增入队；先核在途 Run 并按授权处理，不靠改负责人来取消。保留关联与审计，撤私网试点入口；数据库从受控备份恢复。生产仍由原协调层和信箱路径服务。
