# ADR-001　云端 Dot 直接操作 Multica

**状态**　Proposed · 2026-11-20。公子要求整理完整方案、并行推进工程任务，由主会话复核。本记录的决策范围是新增对外的 Multica 操作入口。Mac 协调桥退役、现有信箱数据库留在 win-work、工作区与项目岗位职责已有各自的采纳记录。[既有跨端决策](https://github.com/CF-FE/task-mailbox-mcp/blob/55217ff344021c34d227ac26fe38de61826bc3e3/docs/decisions/001-task-collaboration-platform.md) · [岗位规范](../../skills/workspace-coordination/SKILL.md)

## 问题和证据

CLOU-21 中，G8 从原会话投件，操作者建卡并指派，Mike 在真实 Run 内读取已存决定并回原 job。随后转入 `in_review` 意外触发项目既有复审。G8 缺少独立建卡和核对派发副作用的入口。工作区没有周期收信的 Autopilot，腾讯云的一分钟轮询用于已登记 Run 的异常补报。Vultr 到腾讯云私网的 `/health` 已返回 200，无凭据请求 `/api/me` 返回 401；云端 G8 专属身份的写入仍需取证。[实单记录](../workflow-reporting.md) · [补报器](../tencent-run-reporter.md)

## 决策

Vultr 提供身份受控的 Streamable HTTP MCP，调用腾讯云 Multica 的原生 REST API。只在服务端配置实例地址与凭据，服务端按实例版本选择已经验证的接口。一次调用携带明确动作、实例、工作区、项目和目标对象。跨端委托可以关联原信箱 job；单纯查询和内部项目操作可独立完成。工作区协调员从 Multica 接单，所在工作机继续运行原 harness。

仓库根目录的 [mcp/](../../mcp/README.md) 收纳服务端模块与契约测试，[plugin/](../../plugin/) 收纳云端 Dot 使用的插件素材。仓库级发行检查读取一次上游信息，两边根据同一份能力验证结果更新。Multica 内的 Agent 操作 Skill 与 Dot 端的插件各由自己的宿主加载。

| Dot 发起的业务操作 | 原生事实与调用结果 |
|---|---|
| 找人、看项目与全局进展 | 按授权实例枚举工作区、项目、现任协调员和负责人，按需列 Issue、Run、阻塞与产物引用。每项结果带查询范围、来源、时间和分页边界。新工作区按任职登记解析，项目负责人空缺如实显示 |
| 立项、规划和交接 | 在明确工作区创建或关联项目，在所属项目创建或复用 Issue、子任务，调整优先级、期限和承接人。回读对象 UUID、项目归属及实际出现的 Run |
| 派发、跟进、返工和终止 | 指派、静默备注、引导指定在途 Run、进入复审、重跑、取消分别建模。返回写入对象及副作用。取消请求须等原 Run 终态才能报告停止。确认业务完成须有指定验收人及其结论 |
| 交付、报告和对账 | 关联原 Issue、历次 Run、产物、原 job、结果版本及实际读确认。需要 Dot 即时获知时单独核对唤醒路径，信箱与补报故障只影响相应回程 |

Dot 对现有和新增项目的业务授权由岗位规范确定，原生凭据与工作区资格由实例所有者配置。跨实例使用稳定的实例标识与原生 UUID。新增 VPS 或工作区时登记服务归属、账号、网络路径和岗位，交接在途原单。治理凭据、数据库管理、宿主 shell 与任意 URL 均有各自独立的权限入口。[身份与工作区](002-identity-and-workspaces.md)

### 谁负责写入和恢复

| 组件 | 持有的数据与动作 |
|---|---|
| Vultr 上的 Multica MCP | 认证主体、标准化指令、稳定请求 ID、请求摘要、派发进度与原生关联。只恢复已受理的指令。断线后先按原标识查实际对象及执行状态。一个请求由一个派发者负责。[派发合同](003-command-delivery.md) |
| 腾讯云 Multica | 工作区、任职、项目、Issue、工作流、Run 和交付物的原生事实。Win、Mac 的运行时按原生队列领单，Mike 继续使用 win-work OMP |
| Task Mailbox 与腾讯云补报器 | 信箱管理原件、结果版本与读确认。补报器在登记范围内发送运行事实。信箱里的文字和调用方填写的 sender 只是任务数据，显式交办须来自已验证的调用者。[跨端回程](004-reporting-and-recovery.md) |
| Decision Service 与项目负责人 | 有实质取舍时记录建议。岗位责任人给出指令，实际执行方登记采用结果，指定验收人审阅交付物。[协作规范](../../skills/workspace-coordination/SKILL.md) |

### 版本和降级

公开能力按业务动作定义，Multica 路径、字段及隐式触发行为集中在原生适配器。公子指出上游可能一周发布两次。维护方应持续发现正式发行，分别记录候选版、按能力核过的版本、各环境实际运行版本。允许增加未知字段；必需字段、鉴权、分页、项目归属、派发或静默语义变化时暂停受影响能力。上一版本的记录及无关能力保留。候选版用隔离实例运行读写契约，真实生产升级沿腾讯云手册执行。[上游兼容策略](005-upstream-compatibility.md) · [升级与恢复](../tencent-upgrade.md)

## 备选和后果

协调员定时读信可以复用 OMP，但查询原始状态仍需代办，每个工作区有空跑成本。统一收信程序适合已认证的单向入件，要满足交互查询、改派和取消仍须再定义命令接口。原生 Autopilot 的 webhook 适合固定自动化，其幂等约定不能推出普通 Issue 写接口也支持同一约定。版本适配器带来维护成本，换取明确的身份、动作、重试责任和事实来源。若上游日后提供可直连自托管实例的官方 MCP，以本套身份、命令和回执验收用例比较替换成本。

## 复核和回退条件

用同一指令从 Dot 创建或复用目标项目的一张卡，见到接手与真实 Run，再核原 job 的结果、摘要、原 Dot 签收及指定验收人。隔离验证并发重投、提交后断线、运行机离线、新工作区、换任与只读回报。检查实际调用与 Run 数，避免静默操作触发额外执行。上线后可停接新写、保留查询，先核持久请求与在途 Run，再交还原生协调员。网络异常时不开放腾讯云公网或恢复 Mac 桥。[任务与证据](../multica-backend-tasks.md)
