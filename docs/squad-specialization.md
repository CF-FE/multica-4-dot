# 小队专精建设指引

建队时先把专精写成一句话：在什么情况下接手，交付什么，谁能凭什么证据验收。查已有角色和小队是否能承接，再确定队长、成员和分工。授权、独立复审、业务验收沿用所属项目与原 Issue 的约定。[角色库](role-library.md) · [小队派工和独立复审](../skills/workspace-coordination/SKILL.md#小队派工和独立复审)

## 可直接填写的小队指令

> 本队承接〔一类真实问题〕，依据〔输入、版本和授权〕交付〔结果〕，由〔验收人〕按〔标准〕核收。队长负责接单、分工和沿原卡汇总；需要独立复核时由未参与该版制作的人承担。新项目接单先查〔方法索引〕，实际用上后由队长在原卡交付或提交审核结论时记录适用条件、结果和证据，将新增经验补回索引原条目与对应 bank 原文档。

## 两个已配置的小队

| 小队 | 交付结果 | 证据入口 |
|---|---|---|
| 开发 | 可直接使用的组件或可照做的方法，附最短示例与验证 | [开发小队工程复用索引](development-reuse.md) |
| 质量 | 同版实物核验、缺陷定位与修复复验、带范围的审查结论 | [质量小队审核方法索引](quality-review-methods.md) |

## 配置与维护

1. 将填写好的指令保存到线上小队，读回完整正文、队长、成员及其实际简报。
2. 沿所属项目原卡检验真实交付，把已验证的结果及适用范围记入小队索引。
3. 业务仓库维护实现、测试、示例或审核方法。原 Issue 留下候选、依据和结论；bank 存可检索的经验，写前按主题与来源查重，写后按原 ID 读回。
