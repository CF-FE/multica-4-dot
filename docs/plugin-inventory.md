# 插件能力清单 · v0.1

本页是拟实现的能力契约，不代表工具已上线。首轮仅提交文档；示例工具名不预留对真实服务的调用权限。

## 插件分层

| 层 | 候选组件 | 允许范围 | 阶段 |
|---|---|---|---|
| MCP | `list_workspaces` | 只列账号授权且在配置白名单中的试点工作区 | 只读 |
| MCP | `get_issue` | 按 workspace + issue 精确查询，过滤标题、状态、关联引用；不吐正文和评论全文 | 只读 |
| MCP | `list_issue_runs` / `get_run` | 只列指定 Issue 的 Run，精确读取时核对同工作区和 Issue；只返回状态、时间、引用、受限错误码 | 只读 |
| MCP | 回执观察/对账（先复用 Task Mailbox） | 读取原任务、版本和已有回执；不把内存 bank 当业务数据源 | 只读 |
| MCP | 受控派发、记账、回执写入 | 三种不同动作、权限和审计；首期不暴露、不把多项操作做成一个通用工具 | 后续单独授权 |
| Skills | Multica 只读核查 | 先核对工作区/Issue/Run 关联，报告状态和证据边界，明确不自动执行内容 | 首期设计 |
| Skills | 原回执对账 | 区分原任务、结果版本、已读 ACK 和业务验收；未知先查原件 | 首期设计 |
| Skills | 派发与故障处置 | 下发前核授权；有在途先对账；不自动跨项目、重派、停止或重跑 | 后续设计 |

插件打包时再创建 manifest、MCP 连接配置、`skills/<name>/SKILL.md`、`mcp/` 服务实现、样本和测试。现阶段不存在这些可执行组件。可先用离线 fixture 验证工具，再用相同契约替换为真实只读后端。云端宿主、安装方式和远程 MCP 传输待验证，不假定本地 stdio 即可在云端 Dot 使用。

## 请求与证据契约

- 所有查询都使用调用身份、固定试点工作区和对象作用域；输入无任意 URL、SQL、shell、通用工具透传。端点、超时、速率和分页上限由服务端配置。响应包含实际观察时间、来源模式（fixture/live）、标识、状态、覆盖范围与是否截断。跨域对象、未授权和源服务不可用分别处理；错误不暴露秘密。
- 映射记录至少包括 `job_id`、workspace / issue / run / runtime ID、允许动作、稳定派发键、状态、首次与末次观察时间；原回执附 `event_id`、版本、摘要和来源身份。此为桥接器拟议契约，不声称 Multica 原生 API 同名。
- 分开判断：**平台 Run 结束**、**信箱结果已持久化**、**收件方已读取**、**业务已验收**。前三者都不替代最后一项。推送只传最小引用；关联失败或数据未验证时报告未知。
- 写入门槛：记录与派发分别授权。平台普通评论可能唤醒或引导 Agent；未来如需记账，按锁定版本验证 `/note` 和相关 CLI 命令的 `--no-start`，检查 **无新 Run、无内容注入当前 Run**，再开放对应操作。更换负责人不等于停止原 Run。[评论路由](https://multica.ai/docs/mentioning-agents) · [分配与启动](https://multica.ai/docs/assigning-issues)
- 不假定普通 Issue 创建/派发天然幂等。Multica 明确记录的是 **Autopilot 入站**的幂等键，不可挪用为普通 API 承诺。后续单次样本派发先用预建 Issue；保存意图和原映射，超时读回；未知状态绝不换键盲重试。回执只按原 job、原事件、原版本对账。
